What Building a Sales Dashboard Taught Me About Data Trust

When I set out to build a Power BI dashboard for a fictional retail/logistics company, I assumed the hard part would be the visuals — picking the right chart types, getting the layout clean, making the KPIs pop. It wasn't. The hard part was the SQL underneath it.

Every dashboard is a promise: this number is true, right now. The moment stakeholders stop believing that promise, the dashboard stops being useful, no matter how polished it looks. I spent most of my time not on Power BI itself, but on data modeling — making sure joins didn't silently duplicate rows, that null handling didn't quietly zero out real values, and that refresh schedules matched how often the underlying data actually changed.

A beautiful chart built on an untrustworthy join is worse than no chart at all — it's confidently wrong.

The turnaround-time win — three days down to same-day reporting — only mattered because the numbers behind it held up under scrutiny. That's the actual lesson: in MIS work, the interface is the easy 20%. The trust is the other 80%.
